# Aula 02 — Processo de design, requisitos e plano de trabalho

## Objetivo
Compreender o processo de Design de Software, levantar requisitos iniciais e organizar um plano de trabalho coerente com o problema e com o contexto do projeto.

## Atividade no projeto do grupo

1. Retome o problema e o contexto registrados na Aula 01.
2. Descreva o processo de design que será seguido no projeto: compreender, levantar requisitos, propor, modelar, implementar, validar e evoluir.
3. Levante requisitos funcionais e não funcionais iniciais do próprio projeto.
4. Organize um backlog ou lista priorizada de necessidades e atividades.
5. Registre um plano de trabalho/checklist e a evidência da atividade no GitHub (Issue/branch/commits/PR).


## Não fazer
- Não transformar solução técnica em requisito sem explicitar a necessidade que a originou.
- Não registrar requisitos genéricos que não tenham relação com o contexto do projeto.
- Não copiar requisitos do NexusLog apenas para reproduzir o exemplo apresentado em aula.

# Entrega — Aula 02
- Descrição resumida do processo de design adotado.
- Backlog ou lista inicial de necessidades do projeto.
- Requisitos funcionais iniciais.
- Requisitos não funcionais iniciais.
- Priorização inicial dos requisitos ou atividades.
- Plano de trabalho/checklist registrado no repositório.
