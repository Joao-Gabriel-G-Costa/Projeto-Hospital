# Aula 03 — Princípios de design, problemas de qualidade, coesão e acoplamento

## Objetivo
Identificar problemas de Design de Software, analisar a qualidade da solução e propor melhorias considerando boas práticas, coesão, acoplamento, duplicação e separação de responsabilidades.

## Atividade no projeto do grupo

1. Selecione uma parte real do projeto que permita avaliar a qualidade do design.
2. Procure sinais de baixa coesão, alto acoplamento, duplicação ou múltiplas responsabilidades.
3. Registre o problema encontrado e explique por que ele prejudica o design.
4. Proponha uma melhoria ou refatoração conceitual sem alterar o comportamento esperado da solução.
5. Registre no GitHub a evidência da análise (Issue/branch/commits/PR), quando aplicável.


## Não fazer
- Não alterar código apenas para aumentar a quantidade de arquivos ou classes.
- Não afirmar que há baixa coesão ou alto acoplamento sem indicar a evidência observada.
- Não copiar a refatoração do NexusLog quando o problema do projeto do grupo for diferente.
- Não introduzir padrão de projeto ou tecnologia sem relação direta com o problema identificado.

# Entrega — Aula 03
- Checklist de qualidade aplicado a uma parte real do projeto.
- Identificação de pelo menos um problema de design, quando existente.
- Evidências relacionadas a coesão, acoplamento, duplicação ou responsabilidades.
- Justificativa técnica da melhoria proposta.
- Proposta de refatoração conceitual ou estrutural, quando aplicável.
- Registro da análise/refatoração proposta no repositório.
